# Deployment: the release pipeline

"Deploying" this repo means publishing a tagged GitHub Release per plugin. There is no server, container or registry. Everything below is read from `.github/workflows/release.yml`, `scripts/generate-release-config.js`, `release-please-config.json`, `README.md` and `CLAUDE.md`.

## Trigger

`release.yml` runs on `push` to `main`, with `concurrency.group: ${{ github.workflow }}` (one run at a time) and a job guard `if: github.actor != 'github-actions[bot]'` so the bot's own sync commit does not re-trigger it. Permissions: `contents: write`, `pull-requests: write`, `issues: write`. Token: built-in `GITHUB_TOKEN` — nothing to configure.

## Steps, in order

1. `actions/checkout@v4`
2. `actions/setup-node@v4` with Node 22
3. `node scripts/generate-release-config.js` — syncs `marketplace.json` and regenerates the Release Please config + manifest from each `plugin.json`.
4. Commit `chore: sync marketplace and release config` as `github-actions[bot]` and push, only if the three files changed.
5. `googleapis/release-please-action@v4`.

Step 3 must also run after a Release PR merge: Release Please bumps `plugins/<name>/.claude-plugin/plugin.json` but cannot reach the root `marketplace.json` (its `extra-files` paths are plugin-relative), so the sync propagates the new version there (comment in `release.yml`).

## Release Please configuration

Generated by the script, not hand-edited:

- `release-type: simple`, `separate-pull-requests: true`, `include-component-in-tag: true`, `include-v-in-tag: true` → one Release PR per plugin, tag `<component>-v<version>`.
- PR title pattern `chore(release): ${component} ${version}`.
- Changelog sections: feat → Features, fix → Bug Fixes, perf → Performance, docs → Documentation, chore hidden.
- `bump-minor-pre-major: false`, `bump-patch-for-minor-pre-major: false`.
- Manifest versions are preserved from the existing `.release-please-manifest.json`; `plugin.json` version is only the fallback.

## Version bumps

| Commit prefix | Bump |
|---|---|
| `feat:` | minor |
| `fix:` | patch |
| `feat!:` / `BREAKING CHANGE:` | major |

A commit bumps only the plugins whose directories it touches (`CLAUDE.md`).

## Repository settings required (README §3)

Under Settings → Actions → General: allow all actions; workflow permissions set so the workflow can write; tick "Allow GitHub Actions to create and approve pull requests". README states skipping the last two yields a `403`. `main` must not require PRs, signed commits or linear history — the bot pushes directly to `main`.

## Recommended flow (README §4)

Work on `dev`, PR into `main`. With squash-merge the PR title is the commit Release Please reads, so it needs the conventional prefix.

## Files the pipeline owns

`.claude-plugin/marketplace.json`, `release-please-config.json`, `.release-please-manifest.json`, `plugins/<name>/CHANGELOG.md`, `plugins/<name>/.claude-plugin/plugin.json` `version`. These are the top git hotspots (`scan`: marketplace.json 11 edits, manifest 9, release config 5).

Failure modes are in [runbooks](runbooks.md). Terms in [glossary](glossary.md).
